# 用户专属工作区与全局 admin 权限设计

**日期：** 2026-08-13

**状态：** 已获用户确认

## 背景

当前 Web 后端把用户保存在 SQLite 的 `users` 表，把工作区成员关系保存在
`workspace_members` 表。创建用户和创建工作区是两个独立 API；同时，工作区鉴权逻辑会让所有
`role == "admin"` 的用户绕过成员关系，因此所有超管实际上都拥有全部工作区权限。

## 需求

1. 每创建一个用户，都自动创建一个以该用户名命名的独属工作区。
2. 用户应成为其独属工作区的 `manager`。
3. 只有用户名正好为 `admin` 且角色仍为 `admin` 的账号拥有所有工作区的全局权限。
4. 其他 `role == "admin"` 的账号不自动加入任何工作区；它们可以创建工作区，也可以通过已有成员管理能力自行加入/被加入具体工作区。
5. 已有工作区和通过手动创建 API 新建的工作区，都应默认让全局 `admin` 成为 `manager`。
6. 既有普通用户和其他超管的成员记录不得被自动清除或覆盖。

## 设计

### 1. 用户工作区 provisioning

在应用层增加幂等的用户工作区 provisioning 流程，而不是让 `AuthStore` 直接操作文件系统：

- 用户创建成功后，创建 `<workspaces_dir>/<username>/workspace.json`，元数据 owner 为该用户名。
- 将新用户加入该工作区，角色为 `manager`。
- 如果全局 `admin` 已存在且不是新用户，则将其加入该工作区，角色为 `manager`；使用现有 `INSERT OR IGNORE` 语义保持幂等。
- 服务启动时，在 seed 用户和默认 admin bootstrap 完成后运行补偿流程：
  - 为历史用户补齐缺失的同名工作区；
  - 为所有可见工作区补齐全局 `admin` 的 `manager` 成员记录。
- 如果同名工作区已经存在但用户尚未创建，则用户创建请求返回冲突，不把新用户绑定到可能包含旧数据的工作区。
- 用户名被直接用作目录名，因此创建用户时拒绝空组件、`.`、`..`、路径分隔符和点前缀等不安全名称。

### 2. 全局 admin 判定

新增统一的全局管理员判定：

```python
user.username == "admin" and user.role == "admin"
```

该判定只用于工作区级权限，不改变 `require_admin` 的语义。`require_admin` 仍然允许所有
`role == "admin"` 的用户执行用户管理、创建工作区等系统管理操作。

### 3. 工作区创建与现有数据迁移

- 手动创建工作区时，创建者继续成为该工作区的 `manager`。
- 同时幂等加入全局 `admin` 为 `manager`。
- 启动迁移不再把所有超管加入无成员工作区，而是只寻找精确用户名为 `admin` 的账号，并将其加入每个工作区；工作区已有其他成员时也要补加 `admin`。
- 其他超管不会因启动迁移、用户创建或工作区创建被自动加入。
- 如果当前没有全局 `admin`，不虚构成员记录；当账号之后创建或被提升为 `admin` 时，再通过同一幂等补偿流程补齐权限。

### 4. 工作区访问控制

将所有“管理员无条件绕过工作区成员关系”的路径收敛到全局 admin 判定：

- `workspace_member` / `workspace_manager` 依赖；
- 工作区列表；
- 跨工作区扫描列表；
- 启动扫描前的工作区成员检查；
- 置顶工作区的成员检查。

因此：

- 全局 `admin` 可以访问、管理所有工作区；
- 其他超管只有在 `workspace_members` 中有成员记录时才能访问对应工作区；
- 其他超管创建的工作区会自动拥有该工作区的 manager 权限，因而仍可自行管理该工作区。

## 一致性与失败处理

SQLite 成员关系和工作区文件系统无法组成单一事务。所有 provisioning 和迁移操作都设计为
可重复执行：重复启动不会重复成员；已存在的工作区元数据不覆盖；单个历史工作区失败不阻断
整个启动流程。用户 API 在工作区冲突或文件创建失败时不应留下一个无法完成 provisioning 的
半成品用户记录。

## 测试范围

- 用户 API 创建用户会同时创建同名工作区，并正确建立用户/admin 成员关系。
- 非 canonical admin 不会被默认加入工作区，且只有创建/被加入的工作区可访问。
- canonical `admin` 能访问已有成员和无成员工作区；已有工作区启动迁移会补齐 `admin`。
- 手动创建工作区会加入创建者和 canonical `admin`，不会加入其他超管。
- seed/bootstrap 与启动补偿对历史用户、历史工作区幂等。
- 不安全用户名和工作区同名冲突被拒绝。
- 现有普通用户成员权限、普通用户工作区列表和成员管理行为保持不变。
