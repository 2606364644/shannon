# 白盒 / 黑盒 扫描页 · 重构设计简报

> 面向 UI 工程师的设计说明。讲清这页**是什么、为什么这么设计、长什么样、怎么交互**，不涉及后端字段或实现参数。
> 视觉示意见 `packages/web/frontend/design-preview/scan-cards-preview.html`（可交互的深 / 浅双主题参考）。

---

## 这页是什么、给谁、要完成什么

supernova 是一个安全审计 / 渗透测试平台。「新建扫描」页是用户每次开启一次任务的入口。来这页的人是安全工程师或渗透测试人员，他们心里已经清楚手里有什么——要么手里有源码、要么手里有一个正在运行的目标地址。他们要在这里快速选定"怎么扫"、配好参数、把任务发出去。

**这页唯一的任务：让"我手里有什么 → 我该怎么扫 → 发起任务"这条路径在三秒内走完，不犹豫、不迷路。**

## 核心想法：从一条 tab，变成两张镜像的「姿式卡片」

常见的扫描页做法是：把扫描类型做成顶部一条 tab，白盒和黑盒各自一套表单。这样有两个问题——一来两种扫法的表单宽窄、结构差别很大，切换时整块区域会变形跳动；二来"选哪种扫法"这么重要的决定，却埋在一个不显眼的小标签里，没有分量。

这次重构的立意是：**把"我从哪一侧接近目标"做成这页的主角。**

- **白盒** = 我掌握源码，由内向外追到漏洞（inside-out）。
- **黑盒** = 我掌握运行中的目标，由外向内打进去（outside-in）。

这是两个方向相反的姿势，所以用**两张面对面、左右镜像的卡片**来表达——而不是两个平铺、无差别的选项框。选定一张，下方展开对应配置；两张卡片始终常驻在顶部，随时可以一键换边。

## 形态：上半选姿式，下半填配置，底部收口

整页是一条自上而下、清晰的纵轴。整体骨架如下（深色示意，浅色同理）：

```
新建扫描 · 从哪一侧接近你的目标？

┌────────────────────┐   ┌────────────────────┐
│ ◐ 源点汇聚 → sink  │   │ 外侧打击 → 靶心 ◑  │
│ INSIDE-OUT         │   │ OUTSIDE-IN         │
│ 白盒审计            │   │ 黑盒渗透            │
│ 你掌握源码…        │   │ 你掌握运行中的目标 │
│ 仓库 · 工作区      │   │ 目标 URL · 认证    │
└────────────────────┘   └────────────────────┘
     （等宽 / 左右镜像 / 选中 = coral 描边 + 右上勾）

┄┄ ⇄ 跨服务关联（默认关） ┄┄

┌ 配置区 · 统一四段骨架（切姿式只换字段、不变形）──┐
│ ▎白盒审计 · INSIDE-OUT              可随时切换 │
│ ▎主要输入   [仓库][仓库] + 添加          必填   │
│ ▎上下文     [工作区]  [分支]             必填   │
│ ▎认证       一行摘要 · 配置登录         可选   │
│ ▎进阶       同时发起黑盒扫描 [开关]             │
└───────────────────────────────────────────────┘
[ ❯ 开始审计 ]                      ⌘+Enter 提交
```

各分块详解：

### 顶部 · 两张姿式卡片（取代旧 tab）
左卡 = 白盒审计，右卡 = 黑盒渗透，等宽并排。每张卡包含：

- 一个能"读出方向"的图形（见下文 signature）；
- 一行小字标签：`INSIDE-OUT` / `OUTSIDE-IN`；
- 卡片名：白盒审计 / 黑盒渗透；
- 一句话说清"你手里有什么、这姿式会做什么"；
- 一行小字列出你将要填的东西（白盒：仓库 · 工作区；黑盒：目标 URL · 认证）。

未选中时安静内敛；选中时整张卡获得 coral 色描边、柔光浮起、右上角出现一个小勾。

### 姿式区下方 · 一条虚线的「跨服务关联」
原来占第三个 tab 的关联扫描，降级成一条默认关闭的轻量开关。它不是每次都要走的主路径，不该和白盒 / 黑盒抢注意力，但需要时触手可及。

### 中段 · 统一配置骨架
**这是解决"切 tab 就跳布局"的关键。** 无论白盒还是黑盒，配置区都是同一套四段结构：

1. **主要输入** —— 白盒：代码仓库（可多选的标签 + 添加按钮）；黑盒：目标 URL（等宽字体、coral 描边、带"验证"链接）。
2. **上下文** —— 白盒填工作区；黑盒填工作区 + 复用某次白盒结果（最新的那次带 `LATEST` 小标）。
3. **认证（可选）** —— 默认收起的一行摘要 + "配置登录"。
4. **进阶** —— HOST 解析等（黑盒）；或"同时发起黑盒扫描"的接力开关（白盒）。

每段有一个 coral 小竖条 + 标题的眉头，右侧标 `必填 / 可选`。**切换姿式时，这四段的宽、高、间距、节奏完全不变，只换里面的字段**——视觉上零跳动。这是本次重构最重要的体感。

### 底部 · 行动条
一颗 coral 主按钮（白盒 = 开始审计 / 黑盒 = 开始渗透）+ 右侧一句小提示（白盒提示快捷键 `⌘+Enter`；黑盒提示"提交前请确认目标 URL"）。

## signature：让「攻击方向」成为图形本身

这是这页最该被记住的一点，也是它区别于任何通用"二选一"模板的地方。两张卡片上的图形不是装饰图标，而是在**表达攻击方向**：

- **白盒的图形**是「多个源点汇聚到一个 sink」——几个入口点经过几条流线，收束到右侧一个 coral 的点。这正是白盒审计的本质：从代码入口追数据流，一路追到危险的 sink。
- **黑盒的图形**是「从外侧打击一个靶心」——一组同心圆靶，一道 coral 的轨迹从右上方斜插进来命中靶心。这正是黑盒渗透的本质：从外部请求打向运行中的服务。
- 两张卡的流线方向相反：白盒向右汇聚、黑盒向左命中，**在两张卡的中缝相遇**，构成一条隐形的对称轴。inside-out 与 outside-in 就这样用图形说清了，不靠文字解释。

这个方向感要克制地做：线条是单色细线、低对比，只有汇聚点 / 命中点这一个焦点是 coral；选中卡片时线条才整体提亮。**点到为止，不做成插画。**

## 交互特性

1. **点卡片即换姿式**，下方配置区原地换内容、不跳布局（核心体感，反复强调）。
2. **选中态一目了然**：coral 描边 + 柔光 + 右上勾，主按钮文案与底部提示同步切换。
3. **关联扫描默认收起**，需要时点开，不干扰主路径。
4. **认证 / 进阶**用展开式——默认一行摘要 + "配置登录"，需要时才展开，降低首屏噪音。
5. **目标 URL** 在黑盒下是唯一带 coral 描边的输入框，强调"这是你要打的靶子"，并紧挨一个"验证"动作。

## 视觉语言（设计方向，不是实现参数）

延续平台既定的 **Claude 风暖纸张感**：

- 背景是**低饱和的暖灰**（不是奶油色、不发黄发米）；暖来自低饱和，不来自高饱和。
- 卡片靠**一圈极细的 hairline 边框 + 一层很轻的暖色阴影**"浮"起来，而不是靠卡片和背景之间的大亮度差（差几个百分点就够）。
- 主色**只有一个 coral**（橙红色，不是紫），且只用在"选中 / 强调 / 行动"这三件事上，其余一律中性灰。
- 字体沿用 **IBM Plex**：标题可用 **IBM Plex Serif** 增加一点性格；正文用 Sans；所有标签、数据、URL、小标用 **Mono**。
- **深色（暖炭黑）与浅色（暖纸张）两套主题都要成立**；语义色（成功 / 警告 / 危险）在浅色下要把饱和度压低，不刺眼。

整体气质是**安静、专业、有分寸**——像一个趁手的工具，不像一张营销海报。

## 文案口吻

直接、动词驱动、说清"会发生什么"：

- 按钮是"开始审计 / 开始渗透"，不是"提交"。
- 卡片描述是"你掌握源码。从入口追到 sink，定位可利用链"，而不是"利用先进的静态分析能力"。
- 空状态要给出下一步该做什么；错误要说明哪里错了、怎么修——不道歉、不含糊。

## 别做什么（边界）

- **不要**给两张卡加 ①② 编号或"步骤 1 / 2"——这是个选择、不是顺序，编号是假信息。
- **不要**为了"更明显"把背景压深、把 coral 饱和度拉高——暖感来自低饱和，高饱和 + 深底反而吃掉对比、什么都看不清。
- **不要**让两套姿式的配置区长得不一样——统一骨架是这次的核心收益，不能破。
- **不要**引入新的主色或新的字体家族——颜色与字体都沿用现有设计系统。
- **不要**让两卡的方向图形变成装饰性大插画——保持单色细线、单焦点 coral 的克制。

---

## 一句话总纲

> 两张镜像的姿式卡片取代 tab，让"从哪侧接近目标"成为主角；下方一套统一骨架承接所有配置、切姿式零跳布局；用攻击方向的图形作为这页的签名。安静、专业、只在该亮的地方亮一下。
