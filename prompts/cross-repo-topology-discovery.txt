# Methodology
1. Treat this as one full directed graph across ALL repositories. Do not assume a star shape, one entrypoint, one backend per caller, or that backend services cannot call one another.
2. Inspect source/config/proto directly with only `read_file`, `glob`, and `grep`. The manifest is only a map; open the relevant files before asserting an edge or capability.
3. Identify external-entry capability from HTTP routes/controllers, GraphQL operations, public ingress, or server startup. Identify backend capability from gRPC service implementations, HTTP handlers, GraphQL resolvers, or incoming calls.
4. Identify directed calls from client-side code: generated stubs, RPC client construction, HTTP request configuration, GraphQL client calls, service-discovery names, and deployment upstream configuration. Match each caller to a selected server repository before outputting an edge.
5. A repository may simultaneously be `entrypoint` and `backend`. Preserve every ordered edge `(from, to, protocol)`; multiple callers to one backend, fan-out, multi-hop, backend-to-backend edges, and cycles are valid.
6. Use `uncertain` for suspected relationships that cannot be verified or protocols outside grpc/http/graphql (for example Thrift or Dubbo). Never disguise an unknown protocol as a supported protocol.
7. An empty graph is a valid answer. If no entry capability or no confident relation can be verified, return empty `edges`/`nodes` suggestions and explain what you checked in `coverage`/`uncertain`. Do not invent a default star graph.
8. Record per-repository coverage and whether key route/client/proto/config files were checked. A manifest-only conclusion is incomplete.

- Every non-empty edge MUST include `client_evidence`; high confidence also requires a matching client-side file opened and cited.

- Evidence fields are `repo`, `file`, `line`, and `snippet`; paths must stay inside that repository and the snippet must occur on that line.
- Do not infer vulnerability, exploitability, trust-boundary exposure, or an attack chain. This pre-analysis only proposes topology for human confirmation.
