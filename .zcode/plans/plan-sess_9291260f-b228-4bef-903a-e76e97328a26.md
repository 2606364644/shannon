# 让 precheck 认证失败对用户可见具体原因

## 问题
组合扫描在 t0 预验证（validate-authentication）失败时（如登录地址不可达），`AuthValidationResult.failure_detail`（如 "Target unreachable: TCP connect ... refused"）在 `_run_precheck` 返回 False 时被丢弃，只写笼统的 `bb_reason="auth_failed"`；`scan_end.stderr_tail` 也是硬编码的 "combined failed"。前端现成的友好横幅 `RunFailureBanner`（支持 authFailed 分类）只在存在 `bb_runs` 记录时渲染，而 precheck 失败没有 run → 用户只看到「失败」徽章 + "combined failed"。

## 后端改动（packages/web）

1. **`components/scan_manager.py` — `_run_precheck`（L2007-2054）**：确定性失败 `return False` 前，把 verdict 写入任务 session.json（对齐 L2049 `bb_precheck_warning` 的 best-effort 写法）：
   - `bb_failure_point`、`bb_failure_detail`（来自 `AuthValidationResult`，截断 ~500 字符防御）。
   - 三个调用方（`start()` L259、`_combined_kickoff` L1709、`_add_blackbox_run` L1997）无需改判断逻辑，自动受益。

2. **`_ensure_scan_end`（L2073-2085）**：`status=="failed"` 时读 session 的 `bb_failure_detail`/`bb_reason`，拼进 stderr_tail（如 `combined failed: <detail>`），替代裸 "combined failed" —— LiveTab 的 `<pre>` 块即刻变有用，且 SSE `scan_end` 事件也带详情。

3. **run 级同步**：`ScanStore.update_blackbox_run`（scan_store.py L385-419）加可选 `extra: dict` 参数，合并进 run session patch 和匹配的 `bb_runs[]` 条目；`_mark_run` 加 `extra` 透传；`_add_blackbox_run` 失败分支（L1997）从任务 session 读回 `bb_failure_*` 传入。`blackbox_run_detail` API 返回 run 原始 session，零额外代码即透出。

4. **`api/scans.py` `_scan_detail`（L83-117）**：响应增加 `bb_failure_point`、`bb_failure_detail`（从 session.json 透传）。

## 前端改动（packages/web/frontend）

5. **`src/api/types.ts`**：`SessionData` 和 `BlackboxRunSummary` 增加可选 `bb_failure_point?/bb_failure_detail?`。

6. **`src/routes/WorkspaceDetail/runStatus.tsx`**：
   - `RunFailureBanner` 加 `detail?: string | null` prop，在 hint 下以 mono 小字块渲染（样式对齐 auth-verify 页的 failure_detail 红框 / LiveTab stderr_tail `<pre>`）。
   - 补上 `authFailed`（action=`rerunAuth`）的渲染分支：链接到 `/p/${ws}/auth-profiles`（认证配置页，即用户改 login_url 的地方），用新 i18n 键 `runs.bannerAuthProfiles`（zh「前往认证配置」/ en "Manage auth profiles"）。

7. **`src/routes/WorkspaceDetail/ScanDetail.tsx`**：
   - 新增任务级失败横幅：`!loading && status ∈ {failed, crashed, killed} && meta?.bb_reason` 且 run 级横幅未展示（条件同 L278）时，渲染 `<RunFailureBanner reason={meta.bb_reason} detail={meta.bb_failure_detail} ws={workspace}/>`，包 shrink-0 div（对齐 L278-283）。live/report 等所有 tab 顶部均可见。
   - 失败实时刷新：`ScanDetail` 一次性加载 meta，扫描进行中失败时横幅不会出现。给 `ScanProgressOverview` 加可选 `onScanEnd?: () => void` prop（其内部已有 useEventSource，在 events 中出现 scan_end 时回调，避免第三条 SSE 连接），ScanDetail 传 `load`。

8. **i18n（`src/locales/{zh,en}.json`）**：
   - 更新 `workspaceDetail.scans.runs.reasonAuthFailed.hint`：覆盖「凭据无效」和「登录地址不可达/目标未启动」两类原因，引导到认证配置检查登录地址与凭据。
   - 新增 `runs.bannerAuthProfiles`。

## 测试

- **后端**（packages/web/tests，跟随现有 precheck 相关测试模式，如 test_scan_decoupling_invariants.py）：
  - `_run_precheck` 确定性失败写 `bb_failure_point/detail`；
  - `_ensure_scan_end` 失败时 stderr_tail 含详情；
  - `_scan_detail` 透出新字段；
  - `update_blackbox_run` 的 `extra` 合并进 run session 与 bb_runs 条目。
- **前端**：新增 ScanDetail 任务级失败横幅测试（mock getScan 返回 failed + bb_reason=auth_failed + bb_failure_detail + 空 bb_runs，断言标题/详情/认证配置链接）；如 runStatus/ReportTabCombined 已有横幅测试则补 detail prop 断言。

## 明确不做
- 不改 `AuthValidationResult` 的 failure_point 枚举（不可达被 agent 归为 username_or_password 属上游行为，hint 文案 + 原始 detail 展示已解决 UX）。
- ScanList 列表行不加失败原因提示（可作后续）。
- 历史已失败扫描无 `bb_failure_*` 字段 → 横幅仍显示（reason 在），只是没有 detail 行，自然降级。
