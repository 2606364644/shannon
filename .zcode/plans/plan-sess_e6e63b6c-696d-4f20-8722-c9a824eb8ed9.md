# PoC 质量优化：修上游数据（路由 + witness）+ 补 gap-fill 上下文

三块改动，按依赖顺序实施，每块独立可回退（全部有 graceful fallback）：

## 改动 1：GitNexus builder 记录 HTTP 路由（复用已有 entry_points 解析）

路由注解解析已存在（`entry_points.py` 五语言全覆盖，结果已落盘 `code_index.json`），只是 chain-verdict activity 没传给 builder。authz 轨的 `_endpoint_label`（`authz_gitnexus_track.py:403-408`）是现成 join 先例。

1. `packages/core/src/supernova_core/code_index/chain_verdict.py`：新增共享 helper `http_route_label(entry_point_id, entry_points) -> str | None`——按 `func_block_id` 查 map，`http_method` 和 `route` 都存在时返回 `f"{method} {route}"`，否则 None（此时保持现状，LLM gap-fill 兜底）。
2. `packages/whitebox/src/supernova_whitebox/pipeline/activities.py` `run_gitnexus_chain_verdict`（~:1453-1518）：加载 CodeIndex 处已有 `index.entry_points` 在作用域内，构建 `{ep.func_block_id: ep for ep in index.entry_points if ep.route}` 并作为 `entry_points=` kwarg 传给 injection/xss/ssrf 三个 builder（与现有 `sink_call_sites` 穿线同构）。
3. 三个 builder（`injection_builder.py` / `xss_builder.py` / `ssrf_builder.py`）：新增可选 kwarg `entry_points`：
   - inj/xss：命中时 `path = f"{route_label} → {verdict.evidence_chain}"`（evidence 已单独存 `evidence_chain` 字段，无信息丢失）；未命中保持现状。
   - ssrf：`source_endpoint` 从误导性的 `chain.entry_point_id`（FuncBlock id）改为 `route_label or chain.entry_point_id`；`path` 同样加前缀。
   - 不传 kwarg / 查不到 → 行为与现在完全一致（back-compat）。
   - 已知限制：Java 类级 `@RequestMapping` 前缀未合成（entry_points.py 只读方法级注解），miss 时走 LLM gap-fill 兜底，不在本次范围。

下游已验证安全：merge 去重键含整条 `path` 但两轨本就永不匹配（无回归）；黑盒 exploit_executor 整文件注入 prompt 不程序化解析（只受益）；PoC `derive_method_path` 正则直接命中新格式，模板层零改动。

## 改动 2：chain_verdict unparseable 修复（有界重试 + prompt/schema 加固）

根因：openai_compatible 引擎（GLM）不发 schema（端点 400，commit 2ede3e58），只剩 prompt 约束；解析失败后 `judge_chain_verdict`（`chain_verdict.py:273-342`）零重试直接落保守分支（witness=None，置信度坍缩 low）。

1. `chain_verdict.py`：抽 `_parse_verdict_json(raw) -> dict | None` helper（复用 `agents/llm_json.py` 的 `_extract_json_payload`，校验 `verdict` 值合法）。
2. `judge_chain_verdict` 加有界重试（默认 2 次，env `SUPERNOVA_CHAIN_VERDICT_RETRIES`，命名对齐 `SUPERNOVA_POC_MAX_TURNS` 惯例）：
   - 第 1 次重试：轻量转格式调用（照抄 `providers_openai._lightweight_reparse` 模式："将以下内容转为符合 schema 的纯 JSON"），便宜；
   - 第 2 次重试：完整 verdict prompt 重发，末尾加强 JSON-only 指令。
   - 重试耗尽才落保守分支，且 `mismatch_reason` 区分「调用失败/空输出」与「N 次重试后仍 unparseable」（修掉现在两种情况混为一谈的诊断问题）。
3. Prompt/schema 加固：`witness_payload` 加入 required（类型保持 `["string","null"]`，safe 时为 null 不伪造）；prompt 中 witness 指令具体化（"minimal concrete attack payload for this sink, e.g. `' OR '1'='1`; null if safe"）。
4. 保守分支语义不变：不丢报（verdict=vulnerable OR 友好）、witness=None。

## 改动 3：PoC gap-fill 上下文增厚 + 参数位置支持（修"恒 query"）

全部在 `packages/core/src/supernova_core/services/poc_generator.py`：

1. **增厚输入**（`_build_gapfill_prompt` :527-543）：每条漏洞的上下文从 `{ID, param, class, evidence_chain[:300]}` 扩为增加 `sink_call`、`source`、`slot_type`、`mismatch_reason`（有则给），以及 `vulnerable_code_location` / `exploitation_hypothesis`（getattr，ssrf 有值，inj/xss 自动跳过）；`evidence_chain` 截断从 300 提到 1000 字符。保留 "Read that file..." 指令（builder 路由 miss 时仍需要）。
2. **扩展输出**：`GAPFILL_OUTPUT_SCHEMA`（:460-479）和 `llm_fill_gaps` 白名单（:574-581）增加 `param_location`（"query"|"body"|null）和 `body_template`（string|object|null，JSON body 原型或 form 串）；prompt 输出说明同步。
3. **placement 消费**（`_assemble` :406-418）：新增共享 `_infer_placement(vuln, vuln_class)` ——确定性信号（source/evidence_chain 含 `req.body.` / `request.body` / `@RequestBody` / `ctx.request.body` 等 → body；ssrf 非 redirect → body；否则 query）。gap 路径优先级：LLM `param_location` > `_infer_placement` > 现有 class 硬编码。body 时：`body_template` 为 dict → 经 `_coerce_request_body` 归一、若含 param 键则注入 witness；为 str → 替换 `param=` 为 `param=witness`；都没有 → 沿用 form 兜底 `f"{param}={witness}"`。ssrf open-redirect 特例保留。
4. **模板路径同步**（`build_template_spec` :273-280）：inj/xss 的恒 query 改用同一个 `_infer_placement`（修 NodeGoat `req.body.preTax` 落 query 的问题）；ssrf 分支不动。两处刻意对齐的注释同步更新。
5. checkpoint 无需改动（`_spec_to_ckpt`/`_spec_from_ckpt` 只存 query/body，placement 隐含其中）。

## 实施顺序

改动 1 → 2 → 3（上游先修，PoC 层后补），每步带测试。改动 1、2 修好后大部分 GN 条目 `needs_gap_fill` 只剩 witness（改动 2 让 witness 正常流入），改动 3 让剩余 LLM 补缺的质量和参数位置正确性提升。
