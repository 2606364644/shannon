# 修复：组合扫描（带认证）提交后不跳转

## 根因（已确认）

`POST /api/scan` → `ScanManager.start()` 在组合扫描（whitebox + url + 认证）分支里**同步 await `_run_precheck()`**（登录目标站验证，worker 实测耗时 2m10s）。期间 HTTP 请求不返回 → 前端 `submitting=true`、按钮变暗、`nav()` 不执行。

- 公开目标（无认证）的组合扫描：`config_path=None` → `_run_precheck` 立即 return True → 正常跳转（已实测复现通过：`/p/__legacy__/scans/.../live`）。
- 带认证的组合扫描：阻塞到预验证结束才返回 → 用户看到「按钮变暗、停留在当前页」。

设计本意（前端测试 `test_combined_precheck...`、`onSubmit` 里 `r.bb_phase === "precheck"` 判断）就是「立即返回 scan_id + bb_phase=precheck，前端立即跳 live 页跟踪预验证进度」，但后端实现把预验证做成了同步阻塞，且 `ScanAccepted` 模型根本没返 `bb_phase` 字段。

## 修复方案（用户已选：后端异步预验证）

把组合分支的「precheck → 白盒提交 → orchestrator」整体挪进一个后台 `asyncio.create_task`，`start()` 写完 session（`bb_phase=precheck`）后立即 `return (ws, scan_id)`。预验证在后台跑，保留「fail → 白盒不跑」语义。前端已就位（`nav(r.scan_id ? .../live : ...)`），live 页已支持渲染 precheck 阶段 + 已 merge `authcheck-events.ndjson`。

## 改动清单

### 1. `packages/web/src/supernova_web/components/scan_manager.py`

**新增 `_combined_kickoff` 后台协程**（紧邻 `_combined_orchestrator`），封装现有组合分支逻辑：

```python
async def _combined_kickoff(self, scan_key, scan_dir, req, config_path,
                            host_mappings, target, event_file):
    """组合扫描后台启动（spec §8.2）：precheck → 白盒提交 → 接力编排。
    start() 把组合分支 fire-and-forget 到此 task，立即返回 scan_id；
    precheck fail → 标 failed + scan_end（白盒不跑），pass → 提交白盒 + 起 orchestrator。
    被 cancel 时（_cancel_combined 已 orch.cancel()）抛 CancelledError 自然退出。
    """
    ws, scan_id = scan_key
    try:
        ok = await self._run_precheck(scan_dir, ws, scan_id, req.url,
                                      config_path, host_mappings=host_mappings)
        if not ok:
            await self._mark_bb(scan_dir, "failed", "auth_failed")
            await self._ensure_scan_end(scan_dir)
            return
        await self._mark_bb(scan_dir, "pending")
        handle = await self._submit_whitebox(target, ws, scan_id, scan_dir, event_file, req.url or "")
        SessionManager(scan_dir.parent).update_session(scan_dir,
            {"source_repo": req.source.value if req.source else None})
        self._handles[scan_key] = handle
        self._tasks[scan_key] = asyncio.create_task(self._watch(scan_key, event_file, scan_dir))
        orch = asyncio.create_task(self._combined_orchestrator(scan_key, handle, scan_dir, req))
        # orchestrator task 与 kickoff 共存于 _orchestrator_tasks？不——kickoff 自己就是 _orchestrator_tasks[scan_key]，
        # orchestrator 需独立追踪。见下方「task 登记」说明。
    except asyncio.CancelledError:
        # _cancel_combined 取消此 task：best-effort 标 cancelled（不重复，cancel 路径已标）
        raise
    except Exception as exc:
        await self._mark_submission_failed(scan_dir, event_file, exc)
    finally:
        self._active_reqs.pop(scan_key, None)
        # kickoff 自身不在此 pop _orchestrator_tasks（见下）
```

**改 `start()` 组合分支**（lines 227-255）：

```python
if req.type == "whitebox":
    if req.url:
        config_path = await self._dump_auth_config(req, ws, scan_dir)
        host_mappings = self._host_config_mappings(host_config)
        SessionManager(scan_dir.parent).update_session(scan_dir, {
            "combined": True, "bb_url": req.url,
            "bb_host_mappings": host_mappings,
            "bb_auth_ref": self._snapshot_auth_ref(req),
            "bb_phase": "precheck",
        })
        # 异步预验证：fire-and-forget kickoff，start 立即返回
        kickoff = asyncio.create_task(self._combined_kickoff(
            scan_key, scan_dir, req, config_path, host_mappings, target, event_file))
        self._orchestrator_tasks[scan_key] = kickoff
        return ws, scan_id          # ← 立即返回，不阻塞
    handle = await self._submit_whitebox(target, ws, scan_id, scan_dir, event_file, req.url or "")
    SessionManager(scan_dir.parent).update_session(scan_dir,
        {"source_repo": req.source.value if req.source else None})
    # 非 combined：不起 orchestrator（原逻辑）
```

注意：`return ws, scan_id` 提前返回会跳过 lines 275-276 的 `_handles[scan_key]=handle` + `_watch` 注册——这正是我们想要的（这两个挪到 `_combined_kickoff` 里白盒提交后做）。`except BaseException` 兜底（lines 267-274）对 combined 分支不再触达（kickoff 内部自处理异常），纯白盒/黑盒分支不变。

**task 登记细节**：`_orchestrator_tasks[scan_key]` 现存 kickoff；kickoff 内部起的 `_combined_orchestrator` 需要也能被 cancel。方案：kickoff 不再单独追踪 orchestrator，而是 `await self._combined_orchestrator(...)`（串行：precheck → 提交 → await orchestrator）。这样 `_orchestrator_tasks[scan_key]` 始终指向唯一可取消 task。需调整 `_combined_orchestrator` 的 `finally` 不再自 pop（改由 kickoff 的 finally 统一 pop），避免 kickoff 还在跑时 orchestrator 先 pop 掉 key。

→ **更简洁的最终结构**：kickoff 内 `await self._combined_orchestrator(...)`（不再 `create_task` 起 orchestrator），`_combined_orchestrator` 去掉 `finally` 里的 `self._orchestrator_tasks.pop`，统一由 kickoff finally pop。这样 cancel 一个 task 即取消整个 precheck+白盒+接力链。

## 不改的部分（零回归边界）

- 公开目标组合扫描：`config_path=None` → kickoff 里 `_run_precheck` 立即 True → 行为不变（仅多一层 task indirection）。
- 纯白盒 / 纯黑盒 / correlation：不走 kickoff，原路径不变。
- `_run_precheck` 本身、AuthValidationWorkflow、live 页 events merge：零改动。
- cancel/delete 语义：`_cancel_combined` 已 pop `_orchestrator_tasks` + cancel，kickoff 被取消后 `await handle.result()` 抛 CancelledError 退出，finally 清理。
