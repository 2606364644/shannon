supernova · 黑盒认证 / 凭据体系重设计
设计提案 · 黑盒扫描认证 + 凭据管理

把「填账号密码」变成编排一组测试身份。

黑盒认证的真正价值不是“能登录”，而是以多个身份登录并比对可访问范围——这是发现 IDOR / 越权的手段。当前页面把多角色当成普通表单行堆在底部，意图完全隐形。本次重设计把每个凭据升格为一张身份卡，把附加角色组织成一条对比阵容，并把凭据管理页从拥挤的表格改成档案卡。

01 · 设计系统

沿用既有 DSF，只新增一个「身份色板」

不另起炉灶。主色仍是 coral、字族仍是 IBM Plex、深 / 浅双主题与 12px 圆角不变。唯一新增的是 5 色身份色板——刻意选在冷色 / 宝石色调，避开既有暖色 severity 梯度（红 / 橙 / 黄 / 琥珀 / 绿），这样「身份」与「验证状态」永远不会撞色。

02 · 签名组件

身份卡 Identity Card

每个凭据 = 一个被测身份。左侧 3px 身份色轨一眼区分「这是第几个身份」；角色名是卡片标题（权限层级最关键），用户名以等宽字体作副标题（操作员控制台的 handle 语汇）；验证状态用独立的 ✓ / ✗ / ● 信号，颜色只来自 severity，与身份色绝不混用。

06 · 改动小结

什么变了，为什么

原状（问题）
  • 多角色 = 底部一行行同质表单，「+ 添加角色」，IDOR 测试意图隐形。
  • 认证配置散落三处（右栏核心 + 底部横向 + 折叠头），登录方式在左、凭据在右、步骤在右栏。
  • 认证管理页是扁平表格，状态徽章 / 测试按钮 / 可展开日志全挤进一个单元格。
  • 验证失败日志是裸 JSON.stringify，未设计。
重设计（解法）
  • 每个凭据升格为身份卡：色轨区分身份、角色名作标题、状态信号独立，意图一目了然。
  • 附加角色组织成对比阵容，表头直接说「分别登录、比对访问范围」。
  • 扫描页沿三段布局不动，只把凭据行换身份卡、附加角色换对比阵容、角色多选换可选身份卡。
  • 认证管理页改档案卡，身份阵容平铺，富内容有呼吸空间。
  • 验证失败日志从裸 JSON 改为步骤时间线，每步状态码 / 耗时一目了然。

实现层面：身份卡是共享组件，扫描页 inline 附加角色 + 档案 dialog 凭据行 + 管理页凭据展示三处复用；既有契约（CredentialDraft、AuthProfileCredential、buildAuthPayload、auth_accounts）与全部测试不变，仅替换展示层。
